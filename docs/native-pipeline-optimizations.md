# Native pipeline changes — 2026-11-02

The implementation follows the current repository rather than assuming every proposed bottleneck still exists. Timing and memory reductions from the proposal are not acceptance criteria without measurements on the target hardware.

| Area | Implemented behavior |
| --- | --- |
| Smart crop | A native ONNX Runtime C++ session owns and reuses input/output tensors. DirectML is preferred; session creation and inference failures can fall back to CPU. Only compact detections return to C#. Bilinear BGRA-to-planar-BGR resizing uses AVX2 gathers/FMA with a scalar fallback/tail. The bundled model expects raw BGR values and top-left padding of 114. AVX2 also reduces the 80 class scores while preserving finite-value checks and earliest-class tie behavior. |
| Translation | The current engine is `QwenTranslationEngine`, already using in-process llama.cpp through LLamaSharp; there is no `LocalModelManager.cs` or subprocess transport to remove. Flash Attention remains enabled. GPU contexts request Q8_0 K/V caches; CPU fallback uses F16. The existing translation, grammar, cancellation and native-runtime ownership remain in place. Total RAM/VRAM savings and model-quality effects have not been measured. Q4 caches and a second C++ llama wrapper were not added. |
| FFT | Pairs of radix-2 stages are fused into radix-4 groups, with AVX2/FMA complex multiplication and scalar fallback. Odd stage counts finish with radix-2. Twiddles are constructed at compile time and aligned to 32 bytes. Numerical comparisons use an absolute error bound against NAudio, allowing FMA's different rounding. |
| Audio | WASAPI capture requests `IAudioClient3` shared-mode minimum period and event callbacks, with a fresh conventional shared-mode client as fallback. Its native thread joins the `Pro Audio` MMCSS task. PCM decoding, RMS, FFT and spectral shaping stay on that thread. The visualizer receives five display levels plus beat information, coalesced at epsilon 0.001, with a 400 ms freshness update for steady signals. The separate raw PCM capture API remains available. |
| Palette | Per-pixel selection uses linearized sRGB and Oklab, processing eight pixels per AVX2 kernel. Scalar conversion remains available. The existing indigo policy is applied to final candidates; HSV is used for those candidates rather than every pixel. Text uses the higher-contrast black/white choice against the selected background. WCAG contrast is tested; APCA was not implemented. |
| Privacy | Native `RegNotifyChangeKeyValue` subscriptions rearm through `CreateThreadpoolWait` before waking the managed worker. HKCU/HKLM ConsentStore changes wake it immediately. Existing process-exit, microphone-level and screen-recording reconciliation remains; this does not make the entire privacy service use zero CPU. |
| Media | A native message-loop thread owns `SetWinEventHook(EVENT_OBJECT_NAMECHANGE)`. It filters top-level `OBJID_WINDOW` / `CHILDID_SELF` events to supported browser/Spotify processes. Notifications invalidate title/URL caches and queue metadata refreshes. Browser and Spotify title scans reuse results between notifications, with a 30-second reconciliation limit. Existing media/timeline heartbeat behavior remains. |
| Sensitive fields | `consteval` transition tries replace rule-by-rule exact and suffix comparisons in the scrubber and clipboard credential labels. Lookup cost depends on field length, not the number of keywords. Existing escaping, Unicode-prefix and suffix-boundary checks remain. This is a field-name trie, not a claim of Hyperscan Teddy throughput over UTF-16 text. |
| Clipboard persistence | Public entry metadata and text/rich-content documents use a native memory-mapped encrypted append log per document. A DPAPI-protected 256-bit root key is loaded once per native store context, and CNG AES-GCM authenticates each record. Existing Personal vault/passcode encryption remains separate. Public image/file attachments keep their existing formats. |

## Clipboard format and migration

The existing per-entry directories and `entry.json` / `content.json` filenames are retained, but new public documents contain binary `VNCLOG1` data. This preserves staging, directory moves, pruning and deletion semantics without introducing a second global index that could disagree with those directories.

- Page 0 stores immutable format metadata and a random file identifier. Pages 1 and 2 hold alternating commit slots. Payload records start on later 4 KiB pages; file growth is rounded to a page so future appends do not rewrite an active record's page.
- A commit contains generation, offset, record size and a tear-detection checksum. Each record carries a fresh 96-bit nonce and 128-bit GCM tag. Associated data binds file identity, record type, length and generation.
- Ciphertext is flushed with `FlushViewOfFile` and `FlushFileBuffers` before a commit is published. The new commit page is then flushed separately. Readers select a complete commit and authenticate its payload. Uncommitted tails are ignored. A torn commit can recover the preceding slot; a committed payload that fails GCM authentication is rejected rather than silently replaced with older content.
- Obsolete versions are compacted into an encrypted temporary file when the log exceeds the larger of 256 KiB and approximately four times the replacement payload. Publication uses an atomic same-directory replacement. No plaintext scratch file is written.
- Startup migrates legacy JSON documents independently. Migration failure preserves the original and allows the legacy reader to continue where possible. New writes can also replace legacy JSON atomically. Serialized plaintext byte buffers are cleared after use.
- The root's hidden `.history-key.dpapi` must be retained with the history. Missing keys do not silently produce replacement keys for existing encrypted records. An empty key file from an interrupted initial creation is recoverable only when no encrypted record exists.

Earlier application builds cannot directly read the new binary documents. This change has been exercised against temporary test histories; the running desktop application and its actual history were not restarted or migrated during this work.

## Dependencies and verification

`Microsoft.ML.OnnxRuntime.DirectML` is pinned to 1.24.4, the available DirectML package found by restore; the former CPU-only package was 1.31.0. Managed/native ORT versions now match. DirectML requires sequential execution and disabled memory patterns; both options are set. Its native runtime and collected redistribution notices are included in the build/publish payload.

The machine used for smoke measurements exposes AMD Radeon Graphics and an NVIDIA RTX 3050 Laptop GPU. The provider requests DXGI adapter 0. Short measurements include native preprocessing, inference, output transfer and NMS; they are not a full hardware benchmark. The regression test checks that repeated native inference allocates zero managed bytes after warmup.

Validation on this workspace:

- Release build, including optimized native linking: **0 warnings, 0 errors**.
- Final related regression selection: **931 passed, 0 failed, 0 skipped**. This includes clipboard storage and UI callers, migration, ciphertext authentication, interrupted commit recovery, missing/wrong keys, incomplete initial key creation, compaction, SIMD/scalar Oklab agreement, bilinear resize, class-score ties, all supported FFT length extremes, registry rearming, audio packet boundaries and lifecycle checks.
- Initial five-run warm smoke means: **DirectML 9.12 ms**, **CPU 25.66 ms**. Repeated native inference allocated **0 managed bytes**. These runs used the same bundled YOLOX model and a synthetic input. The subsequent [controlled pipeline benchmark](native-pipeline-benchmark.md) supersedes these smoke timings: it includes managed/native CPU comparisons, DirectML, repeated kernel/storage measurements, startup cost and observed regressions in complete palette extraction and encrypted clipboard reads.
- Release single-file publish completed. A separate process loaded the published native DLL and bundled model, created a DirectML session and completed inference successfully. `onnxruntime.dll`, `DirectML.dll` and `VNotch.Native.dll` remain outside the managed bundle; both new license collections are present. Unused DirectML debug binaries/symbols are excluded from the publish payload. Probe results are in `artifacts/native-publish-probe.json`.
- The broad clipboard pass initially exposed tests that read raw JSON on disk and a missing-file exception mismatch; both were corrected for the encrypted format. A timing-sensitive menu animation case failed once and passed its isolated retry and the final combined selection. Earlier overlapping test counts are not added to the final count.

Logs and TRX results are under `artifacts/native-opt/` and `artifacts/native-*.log`, including `native-final-tests.log`, `native-final.trx`, and `native-release-build.log`.

NPU execution providers (QNN/OpenVINO), APCA, a claimed 1.2 ms inference time, a 60% FFT cycle reduction, a fourfold palette speedup, and 35% total translation-memory savings are not claimed by this implementation.

The subsequent [palette and clipboard optimization report](native-hotpath-optimizations.md) measures the correction of the two observed regressions. Palette SIMD now also computes angular sectors, chroma and radial weights, including bounded row tails. Public JSON reads use stack/pool buffers and buffered native I/O for small records; mapped reads remain for payloads above 256 KiB. The encrypted format and commit/authentication checks are unchanged.
